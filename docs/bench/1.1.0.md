# Benchmark: sopedu-dns 1.1.0 against other servers

Measured on 10 November 2026. The query stream is private and not in this repository: 12,692 real names (distinct name and qtype) from a home network, about 29% of them blocked by the lists. The tables hold aggregates only, so you can't reproduce these numbers exactly, but the scripts take any list of names; see [bench/competitors/README.md](../../bench/competitors/README.md).

## Summary

- UDP saturation on one CPU core: 103.9k queries per second with a plain upstream and 104.2k with DoH (medians of three runs). Over TCP: 63.2k and 58.0k (one run each).
- Cache-hit p99 at 5,000 queries per second: median 0.75 ms over five passes (0.70 to 3.52 ms). Numa had 1.02 ms and Unbound 2.37 ms over five passes each; the ranges overlap, so none of the three is ranked on it.
- Memory: 18.9 MiB peak process memory (`VmHWM`) with the four lists loaded (744,512 entries, 516,214 unique rules), 19.7 MiB with the DoH upstream. It does not grow under load.
- Every server ran with its query log off: AdGuard Home (`querylog` and `statistics` off), Blocky (`queryLog: none`), Pi-hole (`dns.queryLogging = false`, no database) and sopedu-dns (`query_log_capacity = 0`). Unbound and dnsmasq keep no log. Numa ran with its defaults, apart from its proxy, DoT, mobile API and LAN discovery, which are off.
- AdGuard Home stopped answering in the first UDP saturation run with both upstreams, with its cgroup at the 512 MiB limit.
- With its default query log on, sopedu-dns had a median of 91.9k queries per second and a cache-hit p99 of 1.79 ms; see [the section on it](#sopedu-dns-with-its-query-log-on).

### Why sopedu-dns ran later

The first sopedu-dns run of the evening, just before the others, had the worst cache-hit p99 at 5,000 qps of the fast servers (3.6 ms). The cause was in sopedu-dns: every half second the dashboard's top lists took in all queries since the last update in one step, on the thread that answers queries, and finding the smallest counter scanned every counter. Cache hits waited behind it. The 1.1.0 release fixes that (see the changelog), and the tables below are the fixed build. They run it with the query log off, like the others, which also leaves the fixed code idle; the figures with the log on are in [their own section](#sopedu-dns-with-its-query-log-on).

### Pi-hole

Pi-hole keeps every query in shared memory even with query logging off. With the container's default 64 MiB `/dev/shm` it filled after about 1M queries and FTL exited in the second pure-hit run. The run in the tables gives it a 256 MiB memory-backed `/dev/shm`, counted inside its 512 MiB limit. Pi-hole with its default logging, measured with the others, was slower: 3.7k on the whole stream, 14.1k on pure hits, and 7,994 queries lost at 5,000 qps.

| Server | Whole stream | Unblocked | Pure hits | TCP |

- sopedu-dns used 79-90% of its one core in every saturation run, and dnsperf at most 113% of a core against its 2 CPU limit. Blocky was throttled in 92-98% of CFS periods.
- Saturation runs on this node vary: a run can come in a third below the others (sopedu-dns 63.4k and 68.2k, Unbound 67.7k). Read the medians with the ranges.
- sopedu-dns closes a TCP connection after 65,536 queries (`tcp_queries_per_connection`). It answers what it accepted and closes cleanly, and a client is expected to retry the rest on a new connection (RFC 7766). dnsperf doesn't retry, so the queries it had pipelined past the cap count as lost: 335 and 375 here.

We state an ordering only when the three-run ranges don't overlap and a bootstrap 95% confidence interval of the median ratio excludes 1.0.

- Blocky, Pi-hole and AdGuard Home: sopedu-dns is faster in every three-run column. Against Blocky 6.2 times on the whole stream (7.1 times with DoH). Against Pi-hole 21 times on the whole stream, 29 times on unblocked names and 1.95 times on pure hits. AdGuard Home stopped answering.
- Numa: faster in every three-run column, 2.3 times on the whole stream.
- dnsmasq: 4.3 times on the whole stream and 3.9 times on unblocked names, but in this setup dnsmasq forwards the HTTPS names (24% of the stream) instead of caching them. On pure hits the ranges overlap, so no ordering.
- Unbound: on the whole stream the ranges are separate (101.6-104.0k against 87.2-94.6k) and the interval of the ratio is 1.07 to 1.19, so sopedu-dns is about 10% faster there, with lists loaded against none. The two ran in different sessions of the same evening on a shared node. On unblocked names and pure hits the ranges overlap, so no ordering. TCP is one run each (63.2k against 64.3k), too few to rank.

One pass at 5,000 qps is noisy on a shared node, so sopedu-dns, Unbound and Numa, the three fastest, ran four more hit-only passes each, interleaved (a fresh Pod each time, plain upstream).

## sopedu-dns with its query log on

Out of the box sopedu-dns keeps a query log, which also feeds the dashboard's top lists and the pre-warm tracker. Some of the other servers have no log at all, so the comparison tables leave it off. With it on, on the same setup with the plain upstream:

|---|---|---|
| UDP saturation, whole stream | 91.9k (73.4-101.4k), median of 9 runs | 103.9k (101.6-104.0k), median of 3 |
| Cache-hit p99 at 5,000 qps | 1.79 ms (0.90-3.84), median of 5 passes | 0.75 ms (0.70-3.52), median of 5 |
| Cache-hit p99 at 50 / 500 qps, one pass | 1.41 / 0.96 ms | 1.57 / 1.12 ms |
| Peak process memory (`VmHWM`) | 18.6 MiB | 18.9 MiB |

The build before the fix had 93.4k (74.6-100.6k), so the two overlap and the fix costs no throughput there. The hit-latency passes ran one after another on fresh Pods.

## Fairness notes

- In this setup dnsmasq and Pi-hole (FTL is based on dnsmasq) don't cache HTTPS records, which are 24% of the stream, and forward those names every time. dnsmasq caches only some record types by default; 2.90 and later can cache others with `--cache-rr`, which the bench doesn't set. That explains most of their hit latency, their whole-stream and unblocked saturation, and so most of the 4.3, 21 and 29 times ratios against them.
- Pi-hole ran with `misc.privacylevel = 3` as well as its log and database off.
- Unbound and dnsmasq run without lists and block nothing.
- Cache sizes: sopedu-dns 20k entries and 8 MiB, AdGuard Home 8 MiB, Blocky 20k items, Unbound 64 MiB of messages and dnsmasq 20k entries, all enough for the whole stream. Pi-hole has 10k entries, fewer than the stream's 12.7k names.
